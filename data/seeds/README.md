# data/seeds — SQL Seed Files

INSERT statements generated by `scripts/prepare-db-seeds.ts`.
Apply these **after** the Supabase migration has been executed.

## Files (load order)

| Order | File | Table | Notes |
|-------|------|-------|-------|
| 1 | `001_data_sources.sql` | `data_sources` | No FKs |
| 2 | `002_risk_model_versions.sql` | `risk_model_versions` | No FKs |
| 3 | `003_communes.sql` | `communes` | geometry=NULL until GeoJSON seed |
| 4 | `004_risk_model_coefficients.sql` | `risk_model_coefficients` | → risk_model_versions |
| 5 | `005_commune_risk_profiles.sql` | `commune_risk_profiles` | → communes, risk_model_versions |
| 6 | `006_annual_crime_indicators.sql` | `annual_crime_indicators` | → communes |
| 7 | `007_risk_time_windows.sql` | `risk_time_windows` | → data_sources |

## Apply (when Supabase is configured)

```bash
# Via Supabase CLI
supabase db execute --file data/seeds/001_data_sources.sql
supabase db execute --file data/seeds/002_risk_model_versions.sql
# ... and so on in order

# Or via psql (local dev stack)
psql $DATABASE_URL -f data/seeds/001_data_sources.sql
```

## Important

- Run the migration in `supabase/migrations/` FIRST.
- Load seeds in the numbered order (FK dependencies).
- geometry column in communes is loaded separately from the GeoJSON file.
