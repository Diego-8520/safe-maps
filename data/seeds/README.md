# data/seeds — SQL Seed Files

INSERT/UPDATE statements generated by the seed preparation scripts.
Apply these **after** the Supabase migration has been executed.

## Files (load order)

| Order | File | Table | Notes |
|-------|------|-------|-------|
| 1 | `001_data_sources.sql` | `data_sources` | No FKs — generated by `prepare-seeds` |
| 2 | `002_risk_model_versions.sql` | `risk_model_versions` | No FKs — generated by `prepare-seeds` |
| 3 | `003_communes.sql` | `communes` | geometry=NULL — generated by `prepare-seeds` |
| 4 | `004_risk_model_coefficients.sql` | `risk_model_coefficients` | → risk_model_versions — generated by `prepare-seeds` |
| 5 | `005_commune_risk_profiles.sql` | `commune_risk_profiles` | → communes, risk_model_versions — generated by `prepare-seeds` |
| 6 | `006_annual_crime_indicators.sql` | `annual_crime_indicators` | → communes — generated by `prepare-seeds` |
| 7 | `007_risk_time_windows.sql` | `risk_time_windows` | → data_sources — generated by `prepare-seeds` |
| 8 | `008_commune_geometries.sql` | `communes` (UPDATE) | Sets PostGIS geometry — generated by `prepare-geometry-seed` |

**Important:** Seed 008 UPDATEs existing rows in `communes` — it does NOT insert new rows.
Seeds 001–007 must be applied before 008.

## Prerequisites for seed 008 (geometry)

- PostGIS extension must be active: `CREATE EXTENSION IF NOT EXISTS postgis;`
- This is handled by the migration in `supabase/migrations/20260514_initial_schema.sql`
- Seeds 001–003 must be applied first (communes table must exist and be populated)

## Generate seeds

```bash
# At repo root — requires npm install first

# Generate Excel-based seeds (needs data/raw/safe_maps_dataset_db_ready.xlsx)
npm run prepare-seeds

# Generate geometry seed from GeoJSON (no Excel needed)
npm run prepare-geometry-seed

# Run both and validate in one command
npm run prepare-all-seeds
```

## Validate before applying

```bash
npm run validate-seeds
```

Validates all processed JSON files. Geometry validation runs independently (does not require Excel seeds).

## Apply (when Supabase is configured)

```bash
# Via Supabase CLI
supabase db execute --file data/seeds/001_data_sources.sql
supabase db execute --file data/seeds/002_risk_model_versions.sql
supabase db execute --file data/seeds/003_communes.sql
supabase db execute --file data/seeds/004_risk_model_coefficients.sql
supabase db execute --file data/seeds/005_commune_risk_profiles.sql
supabase db execute --file data/seeds/006_annual_crime_indicators.sql
supabase db execute --file data/seeds/007_risk_time_windows.sql
supabase db execute --file data/seeds/008_commune_geometries.sql

# Or via psql (local dev stack)
psql $DATABASE_URL -f data/seeds/001_data_sources.sql
# ... and so on in order
```

## Important

- Run the migration in `supabase/migrations/` FIRST.
- Load seeds in the numbered order (FK dependencies).
- Seed 008 requires PostGIS active — it uses ST_Multi(), ST_SetSRID(), ST_GeomFromGeoJSON().
- Do NOT commit xlsx/csv files in data/raw/ — they are gitignored.
